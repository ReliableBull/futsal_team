# 웹 서비스 복구 기록 — 2026-09-22

## 확인된 장애

- 외부 주소 `http://49.143.102.211:3932`와 로컬 3000 포트가 연결 거부 상태였습니다.
- 기존 운영 디렉터리 `.next`에는 `BUILD_ID`가 없었고 앱 경로 manifest가 비어 있었습니다.
- 앞선 모바일 API 검증에서 `next dev -p 3101`을 별도 빌드 경로 없이 실행하여 기존 운영 `.next`가 개발 서버에 의해 덮어써졌습니다. 테스트 DB만 분리하고 빌드 산출물을 처음부터 분리하지 않은 작업 실수입니다.

## 복구와 재발 방지

1. 온전한 `.next-mobile-build` 프로덕션 빌드로 3000 포트를 먼저 복구했습니다.
2. `next.config.mjs` 기본값을 개발 `.next-dev`, 운영 `.next`로 분리했습니다. 명시적인 `NEXT_DIST_DIR`은 계속 지원합니다.
3. 웹 서비스를 유지하면서 `.next` 운영 빌드를 재생성하고, 정상 기본 빌드로 서버를 전환했습니다.
4. 서버는 터미널과 분리된 프로세스로 3000 포트에서 실행됩니다. 현재 PID는 `.arena-production.pid`, 로그는 `arena-production.log`에서 확인할 수 있습니다. OS 재부팅 자동 시작 설정을 새로 설치하지는 않았습니다.
5. 운영 시작 스크립트는 폴더 존재 여부 대신 `BUILD_ID`를 확인합니다. 접속 인터페이스를 Next.js의 명시적 `--hostname` 옵션으로 전달합니다.
6. CI API 테스트도 `.next-mobile-test`를 명시하도록 수정했습니다.

## 검증

- 외부 주소에서 홈, 선수 목록, 경기 목록, 명예의 전당, 관리자 로그인 페이지 HTTP 200.
- 각 페이지가 참조하는 JavaScript/CSS 정적 파일 모두 HTTP 200.
- 개발 서버를 3101에서 함께 실행하고 API를 컴파일해도 운영 BUILD_ID, 경로 manifest, required-server-files의 SHA-256이 변경되지 않음을 확인.
- 동시 실행 중 외부 운영 페이지와 정적 파일도 다시 정상 응답 확인.
- DB 읽기 결과 선수 51명, 경기 37건, 포스터 69건. 복구 중 스키마 마이그레이션이나 데이터 수정·삭제를 실행하지 않았습니다.

현재 서버 코드에는 모바일 API도 포함되어 공개 조회는 가능하지만, 운영 DB에는 `MobileSession` 테이블이 아직 없습니다. 모바일 관리자 인증을 완성하려면 별도 마이그레이션 적용이 필요합니다. 웹 관리자 인증은 기존 쿠키 방식을 사용하므로 이 테이블에 의존하지 않습니다. 이번 검증은 웹 페이지와 정적 자원의 응답 및 DB 조회 검증이며, 관리자 계정 로그인·기록 변경은 실행하지 않았습니다.
